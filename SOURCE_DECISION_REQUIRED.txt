CONFLICTS AND AMBIGUITIES REQUIRING DECISION
============================================

CONFLICT 1: Backend Framework - Flask vs FastAPI
------------------------------------------------
Exact Conflicting Requirement:
- Architecture Overview: "Flask: Backend service layer for request handling, routing, and session control"
- Milestones 2, 3, 4: All specify FastAPI implementation (FastAPI Initialization, FastAPI Routes, FastAPI Integration, uvicorn server)

Where It Appears:
- Architecture Overview section: "Core Technologies > Flask: Backend service layer..."
- Milestone 2 Activity 2.1: "Fast API Instilization and import libraries"
- Milestone 2 Activity 2.2: FastAPI route definitions with async/await syntax
- Milestone 3: "MILESTONE 3: Backend - FastAPI Integration (main.py)"
- Milestone 3 Activity 3.4: "__main__: Entry point... starts the server using uvicorn"

Why Implementation Cannot Safely Choose:
Flask and FastAPI have fundamentally different architectures (synchronous vs asynchronous), routing mechanisms, dependency injection systems, and middleware approaches. Choosing one affects every backend file, route definition, middleware configuration, and deployment setup. The document explicitly names both as the core backend technology in different sections.

-------------------------------------------
Exact Conflicting Requirement:

Where It Appears:
- Pre-requisites section: "Watsonx Access and Configuration: Watsonx Overview"
- Project Description: "Using Gemini 1.5 Flash Pro, PocketSmart AI analyzes..."
- Architecture Overview: "Gemini 1.5 Flash Pro: AI model used for..."
- Milestone 1: "Gemini AI Initialization" - all activities reference Gemini API
- All planner scenarios reference Gemini 1.5 Flash Pro

Why Implementation Cannot Safely Choose:
Watsonx (IBM) and Gemini (Google) are completely different AI platforms with different APIs, authentication methods, model capabilities, and SDKs. The prerequisites explicitly require Watsonx setup, but every technical detail, milestone, and code reference uses Gemini. Implementing Watsonx would require rewriting all AI integration code; implementing Gemini contradicts the stated prerequisite.
